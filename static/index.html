The launcher below auto-detects your run.bat (venv) → run_nvidia_gpu*.bat → embedded python → bare main.py; startup streams into the app console.

ComfyUI takes a long time to load its models, so it is left running when you close the studio (or its console window) and is still there next time. Turn this off to have the studio shut ComfyUI down on exit. The Stop button below always works regardless.
ComfyUI keeps every model it has used on the card (the H3 video model, the image model from the last still, the music model from the last song…) and only evicts by its own estimate — after a mixed session a 15 s clip that used to render can die with OutOfMemoryError in the sampler while a 10 s one squeezes in. With this on, each Generate first asks ComfyUI to unload everything and empty its cache (POST /free); the weights come back from RAM in a few seconds. Off = ComfyUI's own management only. 🧹 Free VRAM now does the same by hand, any time.
The MiniMax H3 templates load a 32-billion-parameter text encoder next to the ~21 GB video model. On a 32 GB card the two do not both fit, so a long clip only rendered because ComfyUI offloaded the encoder after encoding — and newer ComfyUI builds ("Using RAM pressure cache") can hold it through sampling instead, which is exactly when a 15 s clip starts failing while 10 s still works. This sets CLIPLoader.device = cpu in the workflow we send, so the encoder lives in system RAM for good and the sampler gets the whole card. It costs roughly two minutes of prompt encoding per run on a 32B encoder, so it is off by default: turn it on only when a render is genuinely short of VRAM. Nothing inside ComfyUI is changed.
Neither hands ComfyUI a bare pipe. On Windows a ComfyUI with piped output and no console can die mid-sampling with OSError: [Errno 22] Invalid argument (the progress bar's stderr flush, ComfyUI-Manager #2458) — a 3 s clip on an empty card fails exactly like a 15 s one. A file write cannot raise that; a real console is what ComfyUI expects. If a render still dies with [Errno 22], press ⤴ below: it stops the ComfyUI H3 started and brings it back in its own window. A ComfyUI you started yourself is never touched.
Off by default: a clip that will not fit is reported, not quietly rendered as two or more segments joined at a hand-off seam. Turn it on only if you would rather have a seam than no clip. While it is off the learned VRAM ceiling below never splits anything either.

A style saves a model, its VAE and text encoders, the sampler settings and a LoRA stack under one name, so the Style dropdown next to the prompt can reproduce a look without retyping five paths. Each style is its own file — styles\<style name>.json — so you can read it, edit it by hand, copy it to another install or back it up on its own. Names therefore have to be unique.

In ComfyUI: open or build the graph (the Template Library has one per model), then Workflow → Export (API) and save it here. The workflow carries its own models — the fields below are optional overrides, and they are ComfyUI dropdown values, not paths on this machine. Video styles

A named ComfyUI video setup: a workflow per generation mode, one or more phases (checkpoint + steps + cfg — Wan 2.2 uses two: high-noise then low-noise), a text encoder, a VAE, LoRAs. Blank fields keep what the workflow already has. MiniMax H3 uses the Settings → ComfyUI templates unless you give the style its own.

Accelerators are injected in front of the sampler at render time — install the pieces first under Settings → ComfyUI → Video accelerators, restart ComfyUI. The ready-made MiniMax H3 SS style ships with Sage auto + Spectrum on.

Phase 1's steps and cfg, the resolution and the aspect are inherited by Basic Settings when the style is picked under the prompt — and Basic Settings is what the render uses, so you can still change them per render. Later phases keep their own steps/cfg.

A chain style runs in two stages: stage 1 generates the guide image, the ControlNet reads it, and stage 2 finishes the picture from that guidance. Saved chains show up in the Image dropdown under the prompt like any style.

Music generation through ComfyUI, by its own worker (music_worker.py). A music style saves the model, its workflow and — the important part — the caption: the Global Metadata / Vocal Details / Arrangement text that describes the sound. That text is reusable across songs, which is what makes it a style. The lyrics are the prompt: type them in the prompt box with [Verse] / [Chorus] / [Instrumental] section tags and press 🎶. Each style is its own file, styles\<style name>.json, in the same folder as image styles, so names are unique across both.

In ComfyUI open the model's template (the Template Library has one), make sure it ends in a SaveAudio node, then Workflow → Export (API) and save the file here. Lyrics, caption, seed, steps, cfg, duration, sampler and scheduler are patched into it on every render.

    default: 0–15, 15–30, …). Each shot renders with its own prompt, shots are
    chained with the usual last-frame hand-off, and the song is muxed over the
    finished cut — the video is frame-exact at 24 fps, so every shot boundary
    lands on the song timestamp it should. Up to 5 minutes.
